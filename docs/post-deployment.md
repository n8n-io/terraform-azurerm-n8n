# Post-deployment setup

After `terraform apply` completes, finish setup by verifying DNS, capturing the n8n encryption key, and activating your n8n Enterprise license. The module deploys the infrastructure and the n8n release end to end — these steps wrap up the operator-side onboarding.

The App Gateway and DNS sections below assume `create_ingress = true` (the default). On a caller-owned ingress topology (`create_ingress = false`, required whenever `create_aks = false`), verify reachability through your own gateway and DNS instead — see [`docs/customer-managed-infrastructure.md`](./customer-managed-infrastructure.md).

## Wait for the Application Gateway

The App Gateway is provisioned during `terraform apply`, but the n8n backend pool only goes Healthy once AGIC has reconciled the Ingress and the n8n main pods have finished their first migration set. Allow 5–10 minutes after apply for the listener to start serving 200s. Verify:

```bash
# Public IP and Azure-assigned FQDN
terraform output -raw appgw_public_ip
terraform output -raw appgw_fqdn

# AGIC-managed Ingress in the n8n namespace
kubectl get ingress -n n8n n8n-ingress
```

The Ingress should report the App Gateway's public IP under `ADDRESS`. If it stays empty for more than 10 minutes, see [`troubleshooting.md`](./troubleshooting.md). Migration ordering is handled chart-side: `helm_release.n8n` runs with `wait = true, atomic = true, timeout = 600` and the chart's Redis-based multi-main leader election (`multiMain.setup`) ensures only the elected leader runs migrations while followers wait for the leader's signal. A `time_sleep.n8n_helm_settle` ([`n8n.tf`](../n8n.tf), default 60 s, configurable via `var.n8n_helm_post_install_settle_seconds`) gates the Ingress so AGIC reconciles against a fully-converged deployment rather than one still rolling.

## Point your domain at n8n

**If you set `create_public_dns_record = true` (and `public_dns_zone_id`):** the public A-record was created during apply by [`dns.tf`](../dns.tf). Delegate the zone at your registrar if you haven't already — the sizing examples expose the zone's NS records via `terraform output -json public_dns_zone_name_servers` (see [`examples/small/README.md`](../examples/small/README.md) for the registrar walk-through). Verify propagation:

```bash
dig +short "$(terraform output -raw n8n_url | sed 's|https://||')"
```

The query should return `terraform output -raw appgw_public_ip` once the registrar's NS delegation has propagated (5–60 minutes).

**If you set `create_private_dns_record = true` (and `private_dns_zone_id`):** the private A-record was created during apply. Resolution works only from inside a VNet linked to the private zone — verify from a pod running on the AKS cluster:

```bash
kubectl run -it --rm dnsdebug --image=busybox --restart=Never -- \
  nslookup "$(terraform output -raw n8n_url | sed 's|https://||')"
```

**If you left both DNS variables unset:** the module did not create an A-record. Add it manually at your DNS provider:

| Type | Name                       | Value                                                            | TTL |
| ---- | -------------------------- | ---------------------------------------------------------------- | --- |
| A    | `n8n` (or your subdomain)  | App Gateway public IP from `terraform output -raw appgw_public_ip` | 300 |

Either approach works equally well for the App Gateway listener; the only constraint is that `var.n8n_domain` resolves to `appgw_public_ip` before browsers can reach n8n.

## Capture the n8n encryption key

The n8n encryption key wraps every credential stored in n8n's database. Losing it makes those credentials unrecoverable on any future cluster — back it up to a password manager BEFORE handing the deployment over to end users.

```bash
terraform output -raw n8n_encryption_key   # save to a password manager
```

The key is generated by `random_password.n8n_encryption_key` ([`n8n.tf`](../n8n.tf)) on first apply and persisted in Terraform state, unless you supplied an existing key via `var.n8n_encryption_key` (the database-restore path, for reusing an existing n8n database's key); the output always reflects the effective key. The output is marked `sensitive = true` so it is redacted from `terraform output` without `-raw`. Store the same value with the operator who handles disaster recovery — without it, a fresh apply against a new database cannot decrypt credentials migrated from a backup of the old database.

If you supplied `var.n8n_encryption_key_secret_ref` instead — pointing n8n at a caller-managed Kubernetes Secret — the `n8n_encryption_key` output is `null`, because Terraform never reads the Secret's value. Back up that key from wherever the caller-managed Secret's contents originated, not from this module's output. See [`docs/customer-managed-infrastructure.md`](./customer-managed-infrastructure.md#kubernetes-secret-references).

## Access n8n and activate your license

Open the URL surfaced by `terraform output -raw n8n_url` in your browser. The first user to land on the page is prompted to create the **owner** account; treat this as the platform-administrator account, not a per-user account.

After signing in:

1. Open **Settings** → **Usage and plan**.
2. Select **Enter activation key**.
3. Paste the key passed via `var.n8n_license_key` (this is the same value the module wired into the n8n Helm release as a Kubernetes Secret — n8n queries the key against the n8n license server on first activation).

The license is now bound to this n8n installation. Subsequent restarts re-validate the binding against the license server; expired or revoked keys cause the **owner** account to lose access to enterprise features but do not block existing user logins.

## Verify the deployment

A handful of post-apply checks that confirm the multi-main topology came up cleanly:

```bash
# 1. Both main pods Ready
kubectl -n n8n get pods -l app.kubernetes.io/component=main

# 2. At least one worker pod Ready
kubectl -n n8n get pods -l app.kubernetes.io/component=worker

# 3. Webhook-processor pods Ready (HPA-managed; minimum 2)
kubectl -n n8n get pods -l app.kubernetes.io/component=webhook

# 4. App Gateway returns 200 on the n8n login endpoint
curl -fsSL "$(terraform output -raw n8n_url)/healthz" -o /dev/null && echo "OK"
```

For a single-shot end-to-end check that exercises every layer (AKS API, namespace, pod readiness, App Gateway HTTPS, n8n license), see `tests/scripts/smoke-test.sh` (US-041) — runnable manually after `terraform apply`.

## Useful outputs at a glance

| Output                     | When you need it                                                                                     |
| -------------------------- | ----------------------------------------------------------------------------------------------------- |
| `n8n_url`                  | The public URL — paste into a browser, also the value to share with end users.                        |
| `appgw_public_ip_address`  | The IP the `var.n8n_domain` A-record must resolve to (root module output; `appgw_public_ip` on the sizing examples). |
| `appgw_fqdn`               | Azure-assigned `<prefix>-n8n.<region>.cloudapp.azure.com` — useful as a CNAME target.                 |
| `aks_cluster_name`         | Pass to `az aks get-credentials --name <this> --resource-group <your resource group>`.                |
| `aks_resource_group`       | Sizing-example output (`azurerm_resource_group.n8n.name`) — this module itself takes a caller-supplied `resource_group_name` rather than creating one. |
| `aks_kube_config`          | Sensitive local-account kubeconfig block — `terraform output -json aks_kube_config` for ad-hoc `kubectl` without `az aks get-credentials`. |
| `n8n_namespace`            | Always `n8n` — useful for templating `kubectl -n <this>` invocations.                                  |
| `n8n_encryption_key`       | The n8n encryption key — back up to a password manager.                                               |
| `postgres_fqdn`            | Private Postgres FQDN — resolves only from inside the linked VNet.                                    |
| `redis_hostname`           | Redis hostname (TLS port only — non-TLS is disabled).                                                 |
