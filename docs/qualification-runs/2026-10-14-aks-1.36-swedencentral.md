# Targeted live run: AKS 1.35 to 1.36 upgrade, Sweden Central, 2026-10-14

Not a filled-in copy of [`manual-azure-qualification.md`](../manual-azure-qualification.md).
This run checked one behavior the `feat/aks-1.36` change depends on: moving
`aks_kubernetes_version` from `1.35` to `1.36` on an existing module-managed
cluster upgrades only the control plane. It ran on one disposable
`examples/small` deployment. It is not a release guarantee, and no result
transfers to other regions, SKUs, or Kubernetes versions.

```text
Environment:     swedencentral, examples/small (multi-main, Azure Managed
                 Redis over TLS, PostgreSQL Flexible Server).
Starting state:  deployed at the #78 state: KEDA chart 2.21.0, n8n chart
                 1.15.0, n8n image from the chart's appVersion, azurerm
                 4.81.0, helm provider 2.17.0, AKS 1.35. Then upgraded in
                 place through the stack (#79 helm 3, #80 acme 3, this
                 change) one step at a time, with a plan checked before and
                 a clean plan after each step.
Module version:  feat/aks-1.36 before its rebase onto main
Date:            2026-10-14
```

## Result

| Check | Expected | Observed |
|---|---|---|
| Plan | One in-place change: `kubernetes_version` on `azurerm_kubernetes_cluster.n8n`, no node pool change | PASS. `0 to add, 1 to change, 0 to destroy`: `kubernetes_version` `"1.35" -> "1.36"` on `azurerm_kubernetes_cluster.n8n`. |
| Availability during the apply | API server and n8n stay reachable, or recover | PASS. The apply took 177 s. An API server `/readyz` probe and an HTTPS probe of the n8n URL ran every 5 s; all 31 probes of each succeeded. |

| Node pools | Both stay on `1.35` | PASS. Both pools stayed on `1.35.8` (`orchestrator_version` is not set). |
| Workloads | No node drained, no pod restarted | PASS. Every node and every n8n pod (names, creation times, restart counts) unchanged. |
| Follow-up plan | Clean | PASS. No changes. |
