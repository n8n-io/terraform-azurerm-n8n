# Shared responsibility

This module creates and configures an opinionated slice of Azure
infrastructure for n8n: AKS, App Gateway/AGIC (with a WAF policy on the
default `WAF_v2` SKU; the optional `Standard_v2` SKU has none), a
PostgreSQL Flexible Server, Azure Managed Redis, Blob storage, and the n8n
Helm release. It does not, and is not intended to, run the whole platform
for you. This page collects the main ownership boundaries that are otherwise
scattered across the README's "Out of scope" and "Support" sections,
individual variable descriptions, and several other docs, into one table so
a platform partner pricing a build on top of the module has a starting
point. It is not an exhaustive platform-security checklist: review it
against your own security, compliance, and operations requirements.

Read this alongside
[`docs/customer-managed-infrastructure.md`](./customer-managed-infrastructure.md),
which documents the caller-managed *layers* (AKS, Blob, namespace, KEDA,
webhook HPA) this module can hand off entirely, and the per-value Kubernetes
Secret references that let a caller supply specific credentials instead of
letting the module generate them. Secret references cover selected values
only, not a full Secrets layer handoff: `kubernetes_secret.n8n_task_runners`
remains module-created in every mode. The rows below cover responsibilities
that exist regardless of which layer ownership mode is selected.

| Area | What the module does | What the caller owns | Related input / doc |
|---|---|---|---|
| Cluster security add-ons and policy | When `create_aks = true`, creates the AKS cluster, its node pools, and an optional API-server IP allowlist, and can optionally enable the Key Vault Secrets Provider add-on (`aks_key_vault_secrets_provider_enabled`) and KMS etcd encryption with a caller-owned Key Vault key (`aks_kms_key_vault_key_id`). When `create_aks = false`, attaches to the caller's existing cluster and manages none of its settings. | Microsoft Defender for Containers, Azure Policy for Kubernetes, and any admission-control policy are not enabled by the module. For KMS etcd encryption, the Key Vault and key, key rotation, keeping every used key version available, and rewriting existing Secrets after enabling, rotating, or disabling KMS are caller-owned; see [Delivering secrets from Azure Key Vault](./customer-managed-infrastructure.md#delivering-secrets-from-azure-key-vault). The module does not expose these cluster settings, and it only ignores node-count drift on the cluster it creates, so a later `terraform apply` can reverse settings changed outside Terraform (for example with `az aks`). If you need them, bring your own cluster with `create_aks = false` and manage them there. On a module-created cluster, Microsoft Entra ID integration and Kubernetes RBAC through Entra ID are not configured and local accounts stay enabled, so the cluster's kubeconfig is a local-account admin credential. The API server endpoint is public and reachable from any address unless `aks_api_authorized_ip_ranges` is set. If you need Entra ID-only access or a private API server, bring your own cluster with `create_aks = false`. | `aks_api_authorized_ip_ranges`, `create_aks`, `aks_key_vault_secrets_provider_enabled`, `aks_kms_key_vault_key_id`, `aks_kms_role_assignment_enabled`, `aks_kms_cluster_identity_enabled`; [`docs/customer-managed-infrastructure.md`](./customer-managed-infrastructure.md#aks-cluster-create_aks) |
| Network egress and DNS | Uses caller-provided VNet/subnets. When `create_ingress = true`, creates an App Gateway with a public or internal frontend. Creates a private DNS zone and VNet link for each module-managed backing service: PostgreSQL when `create_database = true`, Azure Managed Redis when `create_redis = true`, and Blob (`privatelink.blob.core.windows.net`) when `create_blob_storage = true`. When `create_ingress = true` and `create_public_dns_record = true` (or `create_private_dns_record = true`), creates an `azurerm_dns_a_record` (public) or `azurerm_private_dns_a_record` (private) for the n8n hostname and every additional ingress domain in the caller-supplied zone. | The application DNS zone (`public_dns_zone_id` or `private_dns_zone_id`) is always caller-owned; the module only creates A records inside it, and only when `create_ingress = true` and the matching public or private toggle is enabled. No record is created when `create_ingress = false`, even if a record toggle is left on. The A records are caller-owned whenever the matching toggle is `false`. If your network uses central Private Link DNS zones (for example in a hub-and-spoke design), plan for the module-created private zones listed under "What the module does". DNS resolution for any external PostgreSQL, Redis, or Blob endpoint is the caller's responsibility. No egress firewall, NAT gateway, or user-defined route is created, so the module itself adds no egress restriction. A module-created cluster uses the default `loadBalancer` outbound type, and the module has no input to change it. Topologies that need the `userDefinedRouting` outbound type (see [Customize cluster egress with outbound types](https://learn.microsoft.com/en-us/azure/aks/egress-outboundtype)) need a caller-owned cluster (`create_aks = false`). | `public_dns_zone_id`, `private_dns_zone_id`, `create_public_dns_record`, `create_private_dns_record`; [Prerequisites](../README.md#prerequisites) |
| Secrets and Terraform state | Generates the PostgreSQL admin password when `create_database = true`, the n8n encryption key when neither `n8n_encryption_key` nor `n8n_encryption_key_secret_ref` is set, and the task-runner token, as Terraform-managed values. Can read Blob, OTLP, log-streaming, and extra-env values from variables. | Values that land in Terraform state on the default path include, but are not limited to: `random_password.postgres_admin`; `postgres_external_password` when `create_database = false` and `postgres_password_secret_ref` is unset; the n8n encryption key (generated or supplied through `n8n_encryption_key`); `n8n_license_key` when `n8n_license_key_secret_ref` is unset; `n8n_task_runners_token`; `redis_external_password` when `create_redis = false` and `redis_password_secret_ref` is unset; and, on the active feature paths, `azure_blob_account_key`, `azure_blob_connection_string`, `n8n_otel_exporter_otlp_headers`, `n8n_log_streaming_destinations`, `n8n_extra_env`, and `n8n_worker_extra_env`. The provider also stores computed credentials from the resources the module creates or reads: the AKS cluster's kubeconfig (on a module-created cluster this is the local-account admin credential; with `create_aks = false`, whatever the data source returns for the caller's permissions), the storage account's access keys and connection strings when `create_blob_storage = true`, and both Azure Managed Redis access keys when `create_redis = true`. `n8n_image_pull_secrets` entries are stored in state as part of the module-managed ServiceAccount object (their Secret names, never the registry credentials inside those Secrets). Supplied input values can also appear in saved plan files. Securing the Terraform state backend and any saved plans (encryption at rest, restricted access) is the caller's responsibility in every mode. Route the license key, encryption key, credentials-overwrite payload, external PostgreSQL password, and external Redis password through `n8n_license_key_secret_ref`, `n8n_encryption_key_secret_ref`, `n8n_credentials_overwrite_secret_ref`, `postgres_password_secret_ref` (external database path only), and `redis_password_secret_ref` (external Redis path only, `create_redis = false`; the module-managed Azure Managed Redis instance always uses its own generated access key) to keep those values out of the resources this module manages. The task-runner token has no such alternative and is always module-generated. A `*_secret_ref` only means this module never reads or writes the payload. If the caller creates the referenced Kubernetes Secret with a Terraform resource that sets the ordinary `data` or `binary_data` arguments, the payload lands in that Terraform root's state, whether it is the root that calls this module or a separate one. To keep the payload out of Terraform state, create the Secret without Terraform (for example with `kubectl`, a pipeline that does not use Terraform, or an external-secrets operator), or use the Kubernetes provider's write-only `data_wo` / `binary_data_wo` arguments (Terraform 1.11 or later) with an ephemeral value that nothing else in the configuration stores. | [`docs/customer-managed-infrastructure.md`](./customer-managed-infrastructure.md#kubernetes-secret-references); [Capture the n8n encryption key](./post-deployment.md#capture-the-n8n-encryption-key) |
| TLS certificates | When `create_ingress = true`, attaches the certificate referenced by `app_gateway_tls_cert_secret_id` to the App Gateway listener. When `create_ingress = true` and `app_gateway_keyvault_role_assignment_enabled = true` (off by default), also grants the App Gateway certificate identity `Key Vault Secrets User` on `app_gateway_keyvault_id`. The optional `modules/tls-self-signed` and `modules/tls-letsencrypt` helpers can issue a certificate into a caller-owned Key Vault. | The Key Vault, the certificate, and its renewal and rotation are caller-owned. The root module never creates a Key Vault and does not issue or renew certificates. When the role-assignment toggle is off, granting the gateway identity access to the vault is also the caller's job. | `app_gateway_tls_cert_secret_id`, `app_gateway_keyvault_id`, `app_gateway_keyvault_role_assignment_enabled`; [`docs/tls-rotation.md`](./tls-rotation.md) |
| Backup and restore | When `create_database = true`, configures native PostgreSQL Flexible Server backup retention and optional geo-redundancy (`pg_backup_retention_days`, `pg_geo_redundant_backup_enabled`). When `create_blob_storage = true`, can enable Blob soft delete (`blob_delete_retention_days`, off by default). | Backup retention for an external PostgreSQL server (`create_database = false`) belongs to its owner. Restore testing, cross-service disaster-recovery runbooks, and any backup for Redis or Blob data beyond Blob's own optional soft delete are not provided. Azure Managed Redis has no module-level backup at all. Build a DR runbook around the managed services' native capabilities. | `pg_backup_retention_days`, `pg_geo_redundant_backup_enabled`, `blob_delete_retention_days`; [`docs/deletion-safety.md`](./deletion-safety.md) |
| Upgrades and migration rollback | Supports bumping `n8n_image_tag` / `n8n_chart_version` on an existing deployment, with per-version upgrade notes. `helm_release.n8n` runs with `atomic = true`, which rolls back Kubernetes objects, not database migrations. | Database migration rollback on a failed upgrade is manual. Stop n8n, then either run `n8n db:revert` on the current version once per reversible migration, or restore a PostgreSQL backup taken before the upgrade (required when a migration is irreversible). Then restore the previous tags and apply. | [`docs/upgrading-n8n.md`](./upgrading-n8n.md#rolling-back) |
| Monitoring and alerting | Wires Prometheus metrics, OpenTelemetry, and log-streaming destinations when the caller configures them. | Container Insights / Azure Monitor managed Prometheus, alert rules, and dashboards are not created by the module. | [`docs/observability.md`](./observability.md) |
| Support boundary | Open source, maintained by the n8n Solutions team. | n8n's enterprise Support offering does not cover this module. | [Support](../README.md#support) |

This page does not repeat the full ownership contract for caller-managed
AKS, Blob storage, the namespace, KEDA, or the webhook HPA, or the per-value
Kubernetes Secret reference contract. See
[`docs/customer-managed-infrastructure.md`](./customer-managed-infrastructure.md)
for those.
